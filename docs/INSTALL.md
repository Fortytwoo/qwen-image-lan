# 安装与局域网访问

## 选择地址

`-HostAddress` 是服务电脑正在使用的私有 IPv4，`-Network` 是该 LAN 的 CIDR，`-RpId` 是稳定的域名（通常为 `计算机名.local`）。例如 `192.168.50.10 / 192.168.50.0/24 / my-pc.local` 都只是示例。

可以省略前两个参数让安装器检测唯一的私有默认网关接口；有 VPN、多网卡或多个地址时请明确指定。检查端口 8443 和 1235，已占用时使用 `-Port` 与 `-EnginePort` 换端口。

安装不会创建防火墙规则、DNS 配置、公网穿透、开机启动任务或管理员级设置。Windows 首次运行可能需要本人允许相关 Python 进程在**专用网络**访问；需要手工防火墙规则时，范围应限定为指定网段和 HTTPS 端口，后端端口不对 LAN 开放。

## 幂等与升级

- 默认目录 `%LOCALAPPDATA%\QwenImageLAN`，也支持带空格的自定义目录。
- 不同安装用不同目录和端口，每份数据密钥、CA 和 Passkey 独立。
- 同一配置重复安装复用密钥与证书；改变 RP ID、地址、端口等会停止，不自动覆盖配置。
- 文件升级前保存原代码到安装目录 `backups/`，不会把私有数据复制到源码仓库。
- 升级依赖前先停止此实例，避免 Windows 锁定运行中的 DLL；停止脚本核对 PID、路径、命令行与创建时间。
- IPv4 地址变更、证书更新或机器更名属于迁移，先备份并处理域名和 TLS，再更新配置。原 Passkey 绑定 RP ID，不能静默改域名。

## 其他客户端

只分发本次安装的公开 `service/certs/Qwen-LAN-CA.cer`、CA SHA256 指纹及 HTTPS 入口，不分发 `private/`。

- Windows：把公开 CA 导入当前用户“受信任的根证书颁发机构”，本人核对指纹并确认系统提示。
- macOS：通过“钥匙串访问”导入公开 CA，并按本人的信任决策启用 SSL 信任。
- iOS/Android：使用系统提供的证书安装与信任设置；具体步骤随系统版本变化。
- Firefox 使用独立证书库时可能需要在浏览器中导入 CA。

客户端应能解析 RP 域名到服务 IP。`.local` 在原始部署的 Windows 与 Linux LAN 客户端上实际验证过，但不保证所有路由器、系统或 VPN 环境支持。使用局域网 DNS/客户端解析配置时，记录稳定域名并保留证书与 Passkey 的绑定。

已同步的 Passkey 可直接登录；未同步时，在登录后的 `/passkeys` 页面生成 10 分钟、仅限一次的注册链接，授权新设备。链接接收者可访问该实例全部历史，因此只向授权使用者提供。

## 下载恢复

`*.part` 支持安全续传。现有完整文件必须通过大小和 SHA256 校验；校验失败时脚本停止并保留文件，不自动删除或覆盖。

离线安装将固定清单对应的四个权重放在安装目录 `models/`，两个 ZIP 放在 `downloads/`，再使用 `-SkipDownloads`；仍会校验内容。

使用 Hugging Face 的默认公开下载方式。若作者仓库改成需要授权，脚本会报告 HTTP 错误；不要把个人 Token 填入清单、提示词或 GitHub。
